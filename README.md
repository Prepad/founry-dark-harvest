# Orel Death Aura 1.5.0 (Foundry VTT v13/v14, D&D5e)

Пассивка волшебника: **если любой актёр падает до 0 HP в радиусе**, у владельца волшебника всплывает диалог:

- **Исцелить** → выбрать цель (все player-owned токены в радиусе, включая волшебника), затем бросить кубы по формуле для уровня волшебника. Результат добавляется к HP цели, не выше максимума; ячейки заклинаний не расходуются.
- **Восстановить ячейку** → выбрать уровень ячейки (восстановит +1, не выше max)

## Требования
- Foundry VTT v13 или v14
- System: dnd5e, в версии, поддерживающей установленный Foundry
- Module: **SocketLib 1.1.3+** (активен)

Для обеих версий Foundry подходит [dnd5e 5.3.3](https://github.com/foundryvtt/dnd5e/releases/tag/release-5.3.3), требующий Foundry 13.347+. Ветка dnd5e 6.x рассчитана на Foundry v14; например, [6.0.6](https://github.com/foundryvtt/dnd5e/releases/tag/release-6.0.6) требует Foundry 14.367+.

Модуль использует общий API v13/v14: ApplicationV2, DialogV2 и `canvas.grid.measurePath`. Результаты сверки API и границы проверки описаны в [COMPATIBILITY.md](COMPATIBILITY.md).

## Установка
1. Распакуй собранный `dist/orel-death-aura-1.5.0.zip`. Для опубликованной версии также можно использовать ссылку на `module.json` из манифеста.
2. Скопируй папку `orel-death-aura` в `Data/modules/`.
3. Включи модуль **Orel Death Aura** и **SocketLib**.

После обновления модуля перезагрузи игровой мир и страницы всех игроков, чтобы все клиенты использовали одинаковую версию обработчиков SocketLib.

## Настройка
`Settings → Module Settings → Orel Death Aura`

Нажми **Open Config** (Orel Death Aura — Configure) и настроь:

- **Wizard (Actor)** — выбор волшебника (Character-актёр).
- **Расходуемая особенность (Feature)** — особенность типа `feat` у волшебника с настроенными Uses. Остаток вычисляется как `max − spent`; для старых предметов с `max/value` используется `value`.
  При успешном применении пассивки тратится **1 использование**. Если остаток равен 0 — диалог не откроется. Выбор «без ограничений» отключает расход ресурса.
- **Radius progression (ft), JSON[20]** — радиус активации по уровням персонажа (уровень L берёт `arr[L-1]`).
- **Heal dice progression, JSON[20]** — формула лечения для каждого уровня, например `"1d6"` или `"2d6+3"`. Бросок публикуется в чат.
- **Max restore slot level progression, JSON[20]** — максимальный уровень восстанавливаемой ячейки. В списке доступны только уровни с неполным запасом ячеек.

По умолчанию: радиус 30 ft, лечение `1d6`, предел восстановления — ячейки 9 уровня. Каждая прогрессия содержит 20 элементов, по одному на уровень персонажа.

> Примечание: детектор смерти работает на клиенте ГМа, а диалог показывается владельцу волшебника через SocketLib. ГМ проверяет доступность ресурса и применяет эффект. Отмена, полная ячейка, полные HP, ошибка формулы или неположительный результат броска не тратят использование. При ошибке обновления эффекта модуль возвращает списанное использование.

## Примечания
- Детектор перехода к 0 HP выполняется **только на клиенте активного ГМа**, после сохранения изменения. Изменения HP, инициированные игроком, также обрабатываются.
- Диалоги отображаются **только на клиенте(ах) владельца волшебника (OWNER)**, ГМу не показываются.
- Если у волшебника несколько владельцев-игроков, диалог появится у каждого.

## Проверка изменений

Без запуска Foundry можно проверить синтаксис и регрессионные сценарии на заглушках API (нужен Node.js 18+):

```sh
node --check scripts/orel-death-aura.js
node --test tests/orel-death-aura.test.cjs
```

Проверки на заглушках не заменяют проверку модуля в игровом мире Foundry с dnd5e и SocketLib.

## Сборка релиза

Из корня проекта в PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build-release.ps1
```

Скрипт проверяет синтаксис и запускает тесты, затем создаёт ZIP с папкой `orel-death-aura`, копию манифеста и SHA-256 в `dist/`. В архив входят только файлы модуля и документация. Сборка локальная; публикация в GitHub выполняется отдельно, ссылки в манифесте ведут на существующую ветку `main`.
